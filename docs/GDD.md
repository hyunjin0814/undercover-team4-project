## 2. 설계 철학

### 2-1. 3단계 설계 뼈대
1. **기본 무대** — '수사'와 '검거'라는 명확한 뼈대를 구성한다.
2. **정보 비대칭화** — 본부와 현장이 서로 다른 정보를 보며 대조하도록 만든다.
3. **다양화** — 매 판 새로운 재미를 위해 용의자 유형과 돌발 이벤트를 배치한다.

### 2-2. 정체성
- **추리 게임보다 파티 게임**을 강조한다.
- 범인을 좁혀가는 과정은 **단순화**하고, 실제 **검거 과정에서 다양한 재미**를 느끼도록 설계한다.

### 2-3. 핵심 재미 요소
1. **교차검증 오류 — "남 탓"의 재미**: 구두로만 정보를 교환하기에, 대조 정보가 실시간 변동되거나 소통 오류가 나면 서로를 탓하는 유쾌한 상황이 발생한다.
2. **변수 시스템 — 매 판 다른 경험**: 거수자 혼선, 돌발 이벤트 등 변수가 겹쳐 같은 상황이 반복되지 않는다.

### 2-4. 레퍼런스
- **Papers, Please** — 규정집/서류와 대조해 위조 여부를 판별하는 방식.
- **Lethal Company** — 음성 대화 협력, 실수가 웃음이 되는 플레이.

## 3. 게임 루프

### 3-1. 라운드 구조
게임은 **라운드 단위로 단독 진행**된다. (3일 캠페인 아님.) 각 라운드는 그 라운드 안에서 주어지는 **목표 금액(할당량)** 달성을 목표로 한다.

> **2026-07-28 변경 (#395)** — 할당량의 단위가 *검거 인원 수*에서 **금액**으로 바뀌었다. 진행도는 그 시점에 **유치장에 잡아둔 대상들의 현상금 합**이며, 현상금은 대상마다 다르다(라운드 시작에 범위에서 추첨). 목표를 채워도 라운드가 자동으로 끝나지 않는다 — **본부의 종료 버튼**이 활성화되고 팀이 원할 때 끝낸다. 더 벌고 싶으면 제한시간까지 계속 수사할 수 있다.
> '출근/퇴근', '하루' 등의 표현은 **테마 연출**로만 사용하며, 라운드가 이어지는 캠페인 구조를 의미하지 않는다.

### 3-2. 한 라운드의 흐름
1. **준비 (로비)** — 아이템 구입, 역할 분배 등 사전 준비.
2. **용의자 명단 공개** — 모든 플레이어에게 초기 용의자 명단 공개.
3. **출동** — 각 플레이어가 본부/현장 중 위치를 선택해 이동 (역할 고정 아님).
4. **수사 & 검거** — 제한시간 안에 목표 금액만큼 벌어들인다. 도중 돌발 이벤트·제보 전화 발생.
5. **수사 종료** — 목표 금액을 채우면 본부의 종료 버튼이 활성화된다. 누르면 그 시점에 라운드를 마치고, 안 눌러도 제한시간이 끝날 때 목표를 넘겨 있으면 성공으로 끝난다 (#395).
6. **정산** — 성과급·벌금 정산, 개인 스탯(예: 최다 오검거) 표시.
7. **아이템 구매** — 정산 자금으로 다음 라운드용 추가 아이템 구매.

## 4. 역할 시스템 — 본부 & 현장

본부는 특정 인물의 고정 역할이 아니라 **맵 위의 하나의 "위치"**이다. 그 위치에 있는 플레이어 수만큼 본부 기능이 작동한다.

### 4-1. 유동적 배치 (핵심 설계)
- 누구나 본부 위치에 가면 본부 역할 수행 가능.
- 본부에 인원을 둘수록 현장 인원이 줄어드는 **트레이드오프**.
- 본부에 아무도 없으면 본부 기능 완전 정지 (미니맵·CCTV 열람 불가).
- 설계 의도: "지금 본부에 남을까, 현장에 나갈까"를 매 순간 판단하게 만든다.

### 4-2. 본부 기능
| 기능 | 설명 |
|------|------|
| 미니맵 | 본부 위치에서만 열람. 전체 플레이어 위치 확인. |
| CCTV | 맵 곳곳에 설치. 본부에서 하나씩 전환하며 열람. 미설치 구역은 확인 불가(완전한 정보 아님). |
| 판독 | 현장 구두 설명을 듣고 위조 여부 판단 (5장 참고). |
| 제보 전화 | 간헐적으로 수신. 전화를 받는 행동 자체가 수배 리스트 갱신으로 이어짐. |

**제보 전화 상세:** 전화 내용 자체는 중요하지 않고, 받는 행위가 수배 리스트에 새 용의자를 등록한다. 불규칙한 간격으로 오며, 자리를 비운 사이 오면 응답 없이 끊기고 갱신 기회를 놓친다. → 본부에 최소 1명 상주해야 하는 핵심 이유이자, "전화 오기 전까지만 현장 다녀오자"는 도박을 만든다.

### 4-3. 현장 기능
- 도시를 직접 돌아다니며 용의자 탐색.
- 시민 육안 관찰 → 스캔으로 정보 입수.
- 스캔 정보를 무전으로 본부에 구두 전달.
- 용의자 검거·체포·이송.

### 4-4. 통신 시스템 (초안 — 팀 검토 필요)
게임의 핵심 재미("구두 전달 오류 → 남 탓")와 본부-현장 분리를 성립시키는 근간 시스템.

- **기본: 전역 음성 무전** — 팀 전체가 공유하는 상시 오픈 음성 채널 1개. 본부와 현장은 물리적으로 떨어져 있으므로 거리 무관 무전 방식(근접 음성 아님). UGS **Vivox**로 구현.
- **텍스트 대체 수단** — 음성 사용 불가 유저용 텍스트 채팅 병행 (접근성).
- **핑/마커 (선택)** — 본부가 미니맵·CCTV에서 맵 위치에 핑 → 현장 화면에 표시. 구두 설명 보조.
- **이벤트 연동** — '전자기기 먹통'(6-4) 발생 시 음성이 기계음으로 왜곡된다 → 통신 제한 이벤트가 실제로 작동. **차단이 아니라 왜곡으로 확정** (#372): 완전 침묵은 답답하고 버그로 오인되지만, 망가진 소리는 이벤트 발생을 즉시 알리면서 알아듣기 어려워 통신 제한 목적을 달성한다.
- **아이템 연동 (결정됨 · #108 / PR #255)** — '신호 해석기'(8-3)는 정확한 텍스트를 전원에게 브로드캐스트한다. **먹통 중에도 작동한다** — 텍스트 경로라 '전자기기 먹통'(음성 왜곡)의 영향을 받지 않으며, 이것이 이 아이템의 존재 이유다(먹통 우회 확정). 상시 음성과의 역할 분담: 음성=상시·즉시 / 신호 해석기=정확 텍스트 + 먹통 시 유일 통신.
- **근접 음성 레이어 (결정됨 · #100 / PR #194)** — 전역 무전과 별개로, 현장에서 서로 가까운 플레이어끼리 육성 대화하는 레이어 추가. Vivox **positional(3D) 채널**로 아바타 거리 기반 음량 감쇠(거리비례). **채널 분리 없음** — 본부/현장은 역할이 아니라 장소이므로 전원이 순수 거리 기반으로 참여(근처면 육성, 멀면 기존 무전). 무전=PTT, 근접=오픈마이크. '큰 소리=멀리'(외침)는 v2 유예.

## 5. 수사 & 증거 시스템

### 5-1. 조사 행동
현장직은 시민을 **육안으로 관찰**해 스캔 후보를 추린 뒤, **스캔**으로 세부 정보를 확인한다.
- **육안 관찰**: 스캔 대상을 필터링하는 최소한의 사전 작업(스캔 남발 방지). 외형(몽타주) 기반.
- **스캔**: 3초 홀드, 무조건 성공. 횟수 제한은 없으나 **배터리 자원**을 소모한다.

### 5-2. 스캔 배터리 자원
스캔은 배터리 충전식 스캐너로 진행한다.
- 배터리는 사용할수록 소모되며, **본부의 충전기에서만** 재충전 가능.
- 설계 의도: 스캔 남발을 하드 제약으로 억제하고, "충전"이라는 행위로 **현장-본부 왕복 리듬**을 만든다.

### 5-3. 데이터 스키마
| 구분 | 필드 |
|------|------|
| **프로필** (현장 스캔으로 획득) | 이름 `string`, 종족(인간/로봇) `string`, 세력(문양) `enum` |
| **대조용 데이터** (본부 문서에 정의) | 세력(문양) `enum` |

- 위조 판별의 대조 축은 **세력(문양)**.
- 프로필/대조 데이터는 **ScriptableObject**로 구현.

### 5-4. 본부 판독 (Papers, Please 방식)
현장직은 스캔 결과를 **자동 전송하지 않고 말로 설명**한다. 본부는 구두 설명을 듣고 정보의 **내적 모순(위조 여부)**을 판단한다.
- 예: 현장직 "이 사람 세력 문양이 모래시계에 점 2개야" → 본부가 참고자료와 대조해 위조 여부 판단.
- 스캔 정보에는 텍스트뿐 아니라 **문양** 등이 포함되어, 구두 전달 과정에서 소통 오류가 발생할 수 있다 (핵심 재미).
- 매 라운드 랜덤 매칭 — 본부가 매번 새로 확인해야 함.

## 6. 용의자 & 시민

### 6-1. 범인 유형 (3종)
| 유형 | 반응 트리거 | 행동 패턴 |
|------|-------------|-----------|
| 도주형 | 스캔당함 · 플레이어에게 맞음 | 즉시 도주. 추가 행동 없음 — 순수 추격전. |
| 저항형 | 스캔당함 · 플레이어에게 맞음 | 선제 타격 후 전투 발생. 동료 다수 참여 시 제압 유리. (상세 → 7-4) |
| 순응형 | 맞을 때만 (스캔에는 **무반응**) | 스캔에는 태연하다. 맞으면 도주·저항 중 하나로 돌변하고, 그 유형으로 굳는다. |
> 기존에 고려된 '인질형'은 폐기.

> **반응 트리거 변경: 검거 시도 → 스캔·피격 (2026-07-28 확정, #400, 구현됨).** 예전에는 밧줄 묶기 채널링이 성공하는 순간에만 반응이 터졌다. 이제 **스캔당할 때**와 **피격당할 때** 터진다 — "잡으려 하면 튄다"가 "**의심받으면 튄다**"로 바뀌어 수사 행위 자체가 리스크를 갖는다. 밧줄은 반응 판정이 빠진 **순수 검거 수단**이 됐다.
> - **스캔 반응은 스캔 도중(진행률 기본 50%)에 터진다.** 시작 시점에 도주시키면 도주형은 사거리 이탈로 영영 스캔되지 않고 배터리만 날린다. 완료 후면 아무 대가 없이 정보를 얻는다. 중간이면 "반응이 터진 뒤 **남은 구간을 따라붙어야** 정보를 얻는다"가 되어 판단과 조작이 함께 걸린다. 반응 지점은 인스펙터 노출(`Scanner.m_reactionPoint`).
> - **순응형이 피격으로 뽑은 도주·저항은 1회 확정** — 이후에도 그 유형으로 유지된다. 매 피격마다 재추첨하면 연타 도중 도주↔저항이 오가 전투가 성립하지 않는다.
> - **재발동 없음** — 이미 반응 중(도주·저항)이거나 확보·페널티 상태인 대상은 재판정하지 않는다. **기절 중에도 반응하지 않는다** — 쓰러진 대상은 그대로 잡힌다(테이저 콤보 유지).
> - **위협 대상은 실제 가해자다** — 때린 플레이어에게 반격하고, 스캔한 플레이어에게서 달아난다.
> - **환경 피해는 트리거가 아니다** — 폭탄 폭발(6-4)에 맞아도 반응하지 않는다. 트리거는 플레이어의 타격(진압봉·E 제압)뿐이다. "때린 사람에게 반응한다"가 성립하지 않는 피해까지 넣으면 폭발 한 번에 주변이 전부 도주·저항으로 돌변한다.
> - **밧줄에서 반응이 빠지면서 "함부로 묶을 수 없다"를 지키던 장치도 사라졌다** — 이제는 이미 반응이 시작된 대상(도주·저항 중)이 검거 가능 상태에서 걸리는 것이 그 역할을 대신한다.
> - ⏸ 보류: 본부 CCTV·미니맵 등 **원격 조회가 반응 트리거를 우회하는지**, 스캔 반응이 주변 시민 패닉(6-3)으로 **전파되는지**.

### 6-2. 거수자
범인과 동일한 3가지 반응(도주·저항·순응)을 **무작위로 보이는 가짜 대상**. 반응이 추리의 단서가 아니라 노이즈가 되게 하는 혼선 장치.
- 1차 빌드에서는 무고 시민의 도주/저항이 이 혼선 역할을 한다 (아래 미끼 행동 모델). 위조 정보 기반 경범죄 수입원은 다음 빌드.

> **미끼 행동 모델 (초안 — 팀 검토 필요, 2026-07-11 논의 · 2026-07-13 재정의 · #78):** 스캔·대조 중심 방향에 맞춰 1차 빌드는 **행동을 단서가 아닌 노이즈로** 둔다.
> - 무고 시민도 **스캔·피격당할 때 확률적으로 도주/저항**한다 (시민 반응 가중치로 조절 — 6-1의 트리거 변경 참조).
> - 따라서 **도주/저항 행동은 진범을 특정하는 단서가 되지 못한다** — 행동만 보고 쫓으면 무고 시민을 잡게 된다. 오직 스캔·몽타주 대조만이 진범을 가린다.
>
> **가중치 재조정 (2026-07-28 확정, #400):** 반응 트리거가 검거에서 **스캔**으로 옮겨지면서, 반응이 사실상 진범 tell이 될 위험이 커졌다 — 검거는 이미 대상을 특정한 뒤의 행위지만 스캔은 **아무나 찔러 보는** 행위이기 때문이다. 그래서 무고 시민의 비순응 비율을 20% → **50%로 올린다**.
> - 무고 시민: 순응 0.5 / 도주 0.25 / 저항 0.25 (이전 0.6 / 0.2 / 0.2)
> - 예비 용의자: 순응 0.2 / 도주 0.4 / 저항 0.4 (변경 없음)
> - NPC 15명(예비 용의자 3 + 무고 시민 12) 기준 **반응한 대상 중 진범은 약 30%**다 — 기저 비율 20%에서 크게 벗어나지 않아 "행동만 보고 쫓으면 7할이 오검거"가 유지된다.
> - **판정 2단: 진범 검거 = 성공(10,000), 그 외 검거는 전부 오검거(0, 페널티).** 도주·저항한 무고 시민을 잡아도 오검거다 — 순응 무고자와 동일.
> - 경범죄(도박성 깜짝 판정)는 이번 빌드에서 제외. "위조 정보 소지 → 경범죄"(데이터 기반 수입원)와 관찰형 tell은 **다음 빌드**로 미룸.

### 6-3. 일반 시민
평상시 배회하며, 스캔·피격당하기 전까지는 특별한 반응 없이 돌아다닌다. 반응(도주/저항 등)은 스캔·피격 시에 나온다 (6-1).

### 6-4. 일반 이벤트 (치안 불안 반영)
수사와 무관하게 발생하는 돌발 이벤트. 세계관(치안 붕괴)을 반영한다.

| 이벤트 | 발생 위치 | 대응 |
|--------|-----------|------|
| 전자기기 먹통 | 현장 + 본부 (전역) | 시야 제한 + 무전 음성 왜곡(기계음) + 스캐너 사용 불가, 시간 경과로 자동 해제. 신호 해석기(8-3)의 텍스트만 또렷해 우회 수단이 된다 |
| 거리 난동자 | 현장 | 그 자리에서 저항 — 검거로 진압 (경범죄 처리) |
| 나체 난동꾼 | 현장 | 플레이어에게서 도주 — 쫓아가 제압 (경범죄 처리) |
| 범인 탈출 | 본부 | 침입자가 유치장 자물쇠를 열어 수감범이 탈출 — 다시 잡아 와야 함 (진범이면 할당량 원복) |
| 시한폭탄 | 현장 (+ 본부 매뉴얼) | 현장이 폭탄 특징(선 색·일련번호)을 무전 → 본부가 매뉴얼 규칙으로 자를 선을 판단해 시간 내 해체. 미해체 시 폭발(주변 넉백) |

> 나체 난동꾼은 2026-07-15 팀 확정으로 추가 (#106). 거리 난동자와 함께 스폰형 이벤트 리스트(`SpawnedNpcEventSet`)의 두 항목으로 구현됨 — 행동 모드만 다르다: 거리 난동자=저항(Resist), 나체 난동꾼=도주(Flee).
>
> 범인 탈출(#231): 유치장에 수감자가 있고 자물쇠가 잠겨 있을 때 발동한다(`JailbreakEvent`). **본부 무인 조건은 #311에서 제거** (2026-07-23 확정) — 본부에 사람이 있어도 침입자가 들어오므로, 시민과 구분되지 않는 침입자의 걸음을 알아채고 저지하는 것이 관제의 상시 임무가 됐다. 침입자 NPC가 자물쇠(`JailLock`)까지 걸어가 열면 수감자가 전원 도주하고, 진범은 수배 리스트에 재등재(`WantedListManager.ReinstateByNpcId`)되며 라운드 할당량 진행도에서 1 감소한다(`RoundManager.ReportCriminalEscaped`). 자물쇠는 새 수감자를 받는 순간 다시 잠기므로(`JailZone.Admit`) 연속 발동은 자연히 막힌다. 해제 시도 시작 시 전 플레이어 팝업, 개방(탈출 성공) 시 전 플레이어 경보가 뜬다(#311).
>
> **이벤트 NPC 신병·잔류 규칙 (2026-07-23 확정, #310):** 돌발 이벤트 NPC(난동꾼·침입자)는 제압에 실패해 이탈하거나 소란 시간이 끝나도 **소멸하지 않고 배회 시민으로 도심에 잔류**한다 — 경범죄 마커가 남아 언제든 재검거·인계하면 경범죄로 처리된다("아까 놓친 그 놈" 재발견, 6-5). 인계 판정된 신병은 **진범과 동일하게 유치장에 수감**된다(7-2 원문 규칙 복원 — 이전 "임시 거처 소멸 · 유치장 진범 전용"(#299) 폐기). 경범죄 수감자도 '수감자 존재' 조건을 채우므로 범인 탈출의 무대가 된다. **탈옥으로 방출된 난동꾼은 조용히 섞여들지 않고 원래 소란 행동을 재개**한다(`MisdemeanorLoiterer` — 도주가 가라앉은 뒤 근처 플레이어가 나타나면 저항/도주 소란 재점화, 원래 소란 시간만큼). 반복 수익은 **첫 판정에만 지급**(`ArrestJudge`가 지급 후 마커 보상을 비움)으로 막는다. 잔류 NPC는 라운드 종료 시 일괄 정리된다.

> **시한폭탄(#232):** 현장 한 곳(스폰 포인트 중 무작위)에 폭탄이 설치되고 제한시간 카운트다운이 돈다(`BombDefusalEvent`→`BombDevice`, 라운드당 1개). 본부에는 해체 매뉴얼(`BombManual` — 상호작용하는 책)이 있어 규칙표를 펼쳐 읽고, 현장이 무전으로 불러주는 폭탄 특징(선 색·일련번호)에 규칙을 적용해 **자를 선을 지시**한다 — *Keep Talking and Nobody Explodes*식 본부-현장 협동(2-3·4-4의 핵심 재미를 이벤트로 구현). 규칙은 라운드마다 시드로 재배치돼 외울 수 없고 매번 읽어야 한다(`BombPuzzle` — 매뉴얼과 서버 정답이 같은 시드 퍼즐에서 나와 어긋나지 않는다). 제한시간 내 해체하지 못하면 폭발해 주변 NPC를 넉백시킨다. 전원 다운 상태면 발동하지 않는다(해체하러 갈 현장 인원 필요).

### 6-5. NPC 구성 & 스폰 (초안 — 팀 검토 필요)
한 라운드에 등장하는 NPC 군집 구성. 위조 판별 난이도와 스캔 동선의 원천.

- **구성 3종**: 일반 시민(다수, 배회·패닉) / 용의자(수배 대상) / 거수자(혼선).
- **제안 초기 비율** (프로토타입용, 밸런싱 전제): 총 20~30명 중 시민 ~70% · 용의자 ~20% · 거수자 ~10%. (수치 TBD)
- **스폰**: 라운드 시작 시 맵에 일괄 배치.
- **제보 전화 갱신 방식 (2026-07-27 확정, #102)**: 명단에 추가되는 용의자는 신규 스폰이 아니라 **이미 맵에 있던 NPC가 수배 등록**된다 → "아까 지나친 그 놈"을 다시 찾는 재미. 라운드 시작에 예비 용의자 풀 전체(외형·디코이·몽타주 포함)를 확정해 두고 공개만 나눈다 — 전화 시점에 몽타주를 역생성하면 부합 인원 수를 통제할 수 없어 디코이 설계가 깨진다. 미공개 용의자를 잡으면 오검거다. 수배 HUD 분모는 공개될 때마다 늘어난다(`0/1` → 전화 → `1/2`). 예비 풀이 소진되면 전화가 오지 않는다.
- **분포**: 종족(인간/로봇)·세력(문양) 분포가 위조 판별 난이도를 만든다 (5-3 연동).
- **난이도 조절**: 인원/라운드에 따라 시민 수↑, 용의자:거수자 비율 조정 (12장 보류 연결).
- ⏸ 보류: 정확 수치, 스폰/리스폰 알고리즘, 맵 크기 대비 밀도.

## 7. 검거 시스템

### 7-1. 유형별 대응
| 유형 | 대응 |
|------|------|
| 도주형 | 추격 / 함정 / 본부 공중지원(예시: 맵 클릭 → 바리케이드 낙하) / 제압 후 이송구역까지 이동 |
| 저항형 | 선제 공격 → 전투. 체력이 0이 되면 **기절**(즉시 체포 아님 — 밧줄로 끌어야 신병 확보, #366), 플레이어 패배 시 도주형으로 전환. (상세 → 7-4) |
| 순응형 | 스캔에 반응하지 않으므로 별도 판정·대응 없이 체포 절차 진행. **때리면 도주·저항으로 돌변한다** (6-1) |

> 반응은 검거를 시도할 때가 아니라 **스캔·피격당할 때** 터진다 (2026-07-28, #400 — 6-1). 즉 위 대응은 "스캔으로 신원을 확인하려는 순간" 또는 "타격을 넣은 순간" 시작된다. 밧줄 묶기 자체는 반응을 유발하지 않는다.
>
> **도주로가 막히면 저항으로 돌변한다 (구현됨 — #213 포위, #400 길막).** 도주형은 갈 방향이 남아 있는 한 계속 달아나지만, 사방이 막히거나(포위) 플레이어가 몸으로 길목을 막고 버티면(길막) 약 2초 뒤 돌아서서 저항한다. 몸으로 막는 것이 "가둬서 편하게 묶는" 수단이 아니라 **전투를 부르는 선택**이 되게 하는 규칙이다.

### 7-2. 검거 후 처리
검거해 본부로 넘기면, 본부가 스캔 데이터를 기반으로 **경범죄 / 현상수배 여부를 자동 분류**해 최종 실적에 반영한다.

**분류를 트리거하는 '특정 장소' = 본부 인계존**으로 확정한다 (2026-07-17, #228). 인계존(**판정 구역**)과 유치장(**관리 구역**)은 분리된다:

1. **인계존** — 연행 중인 NPC를 데리고 들어가 **인계 단말에서 상호작용키(E)를 눌러야** 분류(판정)된다. 판정 즉시 연행이 풀린다.
2. **판정 결과별 행선지**:
   - **현상수배범 / 경범죄** → **유치장**으로 이송된다. (판정 시 수갑 반환 절차가 있었으나 밧줄 이관으로 제거됨 — 아래 #369 노트 참조.) 대상은 유치장까지 스스로 걸어가 수용되며, **수용 인원은 본부에서 확인할 수 있다**.
   - **오검거(무고한 시민)** → 그 자리에서 **석방**된다. 시민은 다시 도시로 돌아가 배회한다. (개인별 오검거 기록·페널티는 7-3)

> **수갑 반환 시점 = 판정 즉시(verdict 무관)로 확정** (2026-07-21, #229). 이전 초안의 "수감 대상은 수갑을 찬 채 유치장까지 이동" 규칙을 대체한다 — 반환은 인계존 판정 시 일괄 처리하고, 수감 대상은 맨몸으로 이송된다. 연행 중(Escorted, 인계 전)에는 여전히 수갑을 찬 채 이동한다(10-2). 반환 **방식**은 연행자 인벤토리 회수 우선(꽉 차면 바닥 드롭)으로 갱신됐다 (2026-07-23, #307 — 8-2 참조).

> **검거 수단 수갑 → 밧줄 전면 이관 (2026-07-27, #369).** 기본 검거·연행이 수갑에서 **밧줄**로 완전히 대체됐다. 밧줄은 **소모형이 아니라** NPC에 채워두는 자원이 없다 — 따라서 위 #229/#307의 **"판정 후 수갑 반환"(회수·바닥 드롭) 절차는 통째로 제거**됐다. 판정 즉시 끌기가 풀리는 흐름만 남는다(반환할 것이 없다). 연행 중(Escorted)에는 수갑 대신 **밧줄에 묶여 누운 채 끌려 이동**한다(10-2). 수갑 아이템은 폐기됐다(8-2). 무한 검거를 막는 균형추는 수갑 소모가 아니라 아이템 패널티(#367)가 맡는다.

> **인계 판정 트리거 = 인계 단말 상호작용키(E)로 확정 (2026-07-29, #414).** 인계존 콜라이더에 닿는 순간 자동 판정되던 방식(#59 데모 배선)을 폐기한다 — 넘기는 행위가 플레이어의 명시적 입력이어야 어색하지 않고, 조준 피드백(윤곽선, #184)이 "지금 인계 가능"을 알려 줄 수 있다. 조건은 **연행(끌기) 중 + 존 안에 내려놓기 + 대상이 인계존 안 + 단말 조준**이며, 세 조건이 곧 윤곽선이 켜지는 조건이다. 재판정(#358)은 그대로 허용된다(다시 끌고 와 단말기에 E를 누르면 다시 판정). 판정 이후 흐름(유치장 수감·오검거 페널티·정산)은 바뀌지 않는다.

유치장은 **범인 탈출 이벤트의 무대**이기도 하다 — 자물쇠 개념을 포함한 탈출 규칙은 별도 이슈에서 확정한다.

> **유치장 = 시민이 못 들어가는 물리적 감옥으로 확정 (2026-07-29, #415).** 유치장 내부를 별도 NavMesh 영역(`Jail`)으로 분리하고 일반 시민 NPC의 통행 마스크에서 제외한다 — 배회 시민이 유치장 안에 서 있는 그림이 나오지 않는다. 통행은 **수감 이송에 들어가는 순간에만** 열리므로(`NpcJailedState`) 판정된 대상은 종전대로 스스로 걸어가 수용된다. 유치장은 창살 우리로 둘러싸이고 출입구에는 **미닫이 창살 문**(`JailDoor`)이 있다 — 이 문은 **플레이어만** 막는다. 플레이어는 **상호작용키(E)로 여닫는다**(토글 — 한 번 열면 다시 누를 때까지 열려 있어, 신병을 끌고 드나드는 동안 등 뒤에서 닫히지 않는다). 경찰은 유치장에 드나들 권한이 있으니 자물쇠 잠김과 무관하게 E가 먹힌다. **수감 이송(Jailed) NPC 앞에서는 저절로 열린다** — 스스로 걸어 들어가는 대상이라 열어 줄 주체가 없기 때문이며, 플레이어가 닫아 둔 동안에도 이송 경로는 보장된다. 시민의 진입 차단은 문이 아니라 NavMesh 영역이 담당하므로 **문이 열려 있어도 시민은 들어가지 못한다**. 자물쇠(7-5 범인 탈출)와 문은 **단방향**으로만 이어진다: 자물쇠가 풀린 동안(탈옥)에는 근처에 아무도 없어도 문이 계속 열려 있어 그 자체가 탈옥 신호가 되고, 새 수감자로 재잠금되면 근접 판정으로 돌아간다. 반대로 문이 여닫힌다고 자물쇠가 풀리지는 않는다. 탈옥으로 방출된 수감자는 문 밖 지점으로 나온 뒤 통행을 잃는다(창살 안 고착 방지).

> 반대로 **넘기지 않고 방치하면** 대상이 밧줄을 풀고 달아난다 → 7-6.

### 7-3. 오검거 페널티
**오검거** = 잡아서 본부로 넘겼을 때 **올바른 체포 대상이 아니었던 경우**.

- 오검거는 **두 축으로 집계**된다 — **개인별 기록**(정산 코믹 스탯용)과 **팀 공유 카운트**(페널티 트리거용).
- **오검거당한 시민은 석방 대신 "원한 구역"에 수용**된다 (구역 인원 = 팀 오검거 카운트, #277).
- **팀 카운트가 허용치를 넘는 순간, 원한 구역의 시민 전원이 추격대로 출동**한다 (#278). 추격 NPC에게 잡힌 플레이어(**오검거 원인 제공자가 아니어도**!)가 페널티 대상이 되고, 페널티 NPC들이 **광장까지 끌고 가 30초 매달기(행동 불능)** 후 자동 복귀시킨다 (#279). 추격에는 시간 제한이 없다 — 잡히거나 격퇴로 미뤄질 뿐 사라지지 않는다.
- 정산 화면에 "이번 판 최다 오검거" 등 **코믹한 개인 스탯**으로 표시 (개인별 기록 축).
- 오검거는 **팀 자금·게임오버와 무관**.

> **원한 추격 시스템으로 구체화 (#276~279, `WrongfulArrestPenalty`).** 초기 기획의 "개인 오검거 N회 초과 시 즉시 매달기"는, 팀 공유 카운트 기반의 **시민 추격대 출동 → 광장 호송 → 매달기** 연출로 구현됐다. 억울하게 잡혔던 시민들이 원한 구역에 모였다가, 팀 오검거가 임계치를 넘으면 몰려나와 **아무 플레이어나 붙잡아** 광장으로 끌고 간다 ("억울한 시민들의 복수"라는 코믹 연출). 출동 순간 팀 카운트는 리셋돼, 추격 중 쌓인 새 오검거는 별도 추격대가 된다.

> **삭제됨:** 이전 기획의 '치안 신뢰도(누적 페널티)' 시스템은 전면 폐기. 따라서 오검거가 돌발 이벤트 발생 빈도/수준에 영향을 주는 연결도 제거되었다.

### 7-4. 전투 & 제압 시스템 (초안 — 팀 검토 필요)
저항형·거리 난동자 등과의 물리 충돌을 다루는 공통 시스템. 로봇 경찰의 목표는 **비살상 제압·체포**.

- **저항형 흐름**:
  1. 현장직이 **스캔 또는 타격** → 대상이 **선제 공격**(범위 타격, 플레이어 HP 감소). 트리거는 #400에서 검거 시도에서 옮겨졌다 (6-1).
  2. 플레이어가 반격/제압 시도 → **체력이 0이 되면 기절(Stunned)** — 즉시 체포되지 않는다.
  3. **플레이어 패배(교전 인원 HP 소진) 시 → 대상 도주형 전환** 후 도주 시작. **제압 실패(제한 시간 초과)로 뿌리치는 경로는 폐지됐다** (#366) — 저항형은 체력이 0이 될 때까지 버티며, 물러나지 않는다. **표적을 잃으면 5초 후 배회로 돌아간다** — '잃는다'는 유발자가 **25m 밖으로 달아나거나 다운되는 것**이다(도주의 이탈 거리와 같은 기준). 그 안에 있는 한 계속 쫓는다.

> **NPC 체력 (#366, 2026-07-27 확정):** 저항 제압 게이지를 NPC 체력이 흡수했다. 타격으로 체력이 0이 되면 **기절(Stunned)** 하며, 즉시 체포되지 않는다 — 신병을 확보하려면 밧줄(8-3)로 끌고 가야 한다. 체력은 지속형이라 교전 사이에 누적되고, 기절에서 깨어나는 순간에만 완전 회복된다. **기절이 풀리면 그 자리에 서 있지 않고 도주한다**(#269) — 밧줄로 끌 시간은 기절해 있는 동안뿐이다.
>
> **타격 기절과 테이저 기절은 시간이 분리됐다 (2026-07-28, #400).** 밧줄로 끌 수 있는 창이 곧 검거 난이도라, 전투 결과(체력 0)와 아이템 효과(테이저)를 따로 튜닝한다. 타격으로 쓰러진 기절은 **3.6초**(그중 마지막 0.59초는 일어나는 모션이라 실제로 누워 있는 건 약 3초), 테이저 무력화와 넉백 착지 KO는 **2.67초**를 유지한다. 값은 `NpcStunConfig`의 `KnockdownStunSeconds` / `StunSeconds`. 배회 중인 NPC도 타격 대상이다. 연행·수감·오검거 페널티 진행 중인 대상은 타격이 무시된다(신병 우회 차단).
- **공격은 예고되고, 피할 수 있다 (2026-07-17 추가 — #220):** 저항형의 선제 공격은 즉발이 아니라 **준비 동작(스윙) → 타격**의 단발 스윙이다.
  - **회피 창**: 데미지는 스윙 시작 시점이 아니라 **타격 프레임**에 들어간다. 준비 동작이 곧 예고이고, 그동안 사거리를 벗어나면 **그 타격은 빗나간다**.
  - **정면 판정**: 타격은 NPC 정면 부채꼴 범위에만 닿는다 — 측면·배후로 파고들면 맞지 않는다.
  - 취지: "언제 맞는지 모른다"를 없애고, 저항형 전투를 **읽고 대응하는** 교전으로 만든다. 거리 난동자(6-4)의 타격도 같은 규칙을 따른다.
  - ⚠ **팀 확인 필요** — 이 항목은 기존 7-4의 '즉발 선제 공격' 서술을 바꾸는 **규칙 변경**이다. 회피 창을 열어줄지, 준비 동작 길이·부채꼴 각도를 얼마로 둘지는 플레이테스트로 확정한다(현재 구현값은 인스펙터 노출).
- **제압 조작 (2026-07-23 확정 — #332):** 유형별로 손맛을 가른다.
  - **저항형** = E **연타** — 타격 1회마다 **체력**을 깎는다(구 제압 게이지 — #366에서 체력으로 통합). 여럿이 함께 치면 그만큼 빨리 쓰러뜨린다.
  - **도주형** = E **홀드 3초 채널링** — 붙어서 사거리를 유지한 채 홀드를 채워야 체포된다(사거리 유지가 곧 추격). 뗌·사거리 이탈·대상 상태 변화면 무산. 밧줄 묶기 채널링과 같은 화면 게이지가 표시된다. (이전의 'E 한 번 즉시 체포'는 저항형 연타와의 불균형으로 폐기)
  - **제압 전환 연출**: 저항형은 체력이 0이 되면 **기절해 쓰러진다**(#366) — 서서 헤롱대는 그로기가 아니고, 기절 시간이 끝나면 스스로 일어나 도주하므로 그 전에 밧줄로 끌어야 한다. 도주형은 태클 구르기 → 그로기(연행하러 올 때까지 유지)로 이어진다. 즉시 대기 자세로 스냅하지 않는다.
- **협동 인센티브**: 동료 다수 참여 시 제압 유리 (파티 협동 취지 유지).
- **아이템 연동**: 테이저 건(8-3)은 저항형·도주형 즉시 무력화에 유리.

> **스턴 전 상태 개방 (#292, 2026-07-27 확정):** 테이저는 이제 **NPC가 어떤 상태든** 3초 무력화시킨다. 예전에는 연행·수감·오검거 페널티 진행 중인 대상에게 no-op이었는데, 스턴이 상태 전이가 아니라 **상태 위에 얹히는 플래그**가 되면서 호송·수감·페널티 링크를 끊지 않게 됐기 때문이다 — 3초 얼었다가 **하던 일을 그대로 재개**한다. 배회·반응 중이던 대상만 깨어나며 도주로 전환된다.
>
> **연행 중인 대상만은 예외로 연행이 끊긴다** — 그 자리에 묶인 채(`Captured`) 떨어지고, 데려가려면 다시 E로 끌어야 한다(폭발 넉백과 같은 처리). 재개시켜 버리면 연행 중인 대상을 쏠 이유가 없어 상호작용이 죽는다. 동료의 호송을 끊어 가로채는 **의도된 방해 수단**이다.
>
> **타격은 함께 열리지 않는다.** 연행 중인 NPC를 때려 기절시켜 신병에서 빼내는 우회를 막기 위해, 피해 게이트는 분리해 예전 제외 목록을 그대로 유지한다(연행·수감·오검거 페널티 진행 중이면 타격 무시).
>
> ⚠ **팀 확인 필요 — 페널티 추격대 반격:** 이 변경으로 오검거 추격대(`Chasing` 등)를 테이저로 3초 멈출 수 있게 된다. 7-3의 "추격 회피 수단은 격퇴(호루라기)뿐"(#277~#279) 설계와 갈리는 지점이다. 이 반격을 의도한 것인지 확정이 필요하며, 아니라면 페널티군만 예전처럼 no-op으로 되돌린다.
- **거리 난동자**: 약한 전투, 제압 시 경범죄 처리 + 수익 (6-4).
- ⏸ 보류: 전투 조작 방식(연타 / 조준 사격 / 미니게임 등 — QTE는 이번 수정에서 제외), 데미지·체력 수치.

### 7-5. HP · 다운 · 구조 (초안 — 팀 검토 필요)
플레이어 생존·협동 구조 규칙. HP(내구도, 10-1)의 실제 작동 정의.

- **데미지 소스**: 저항형 전투(7-4), 거리 난동자(6-4).
- **HP 0 → 다운(쓰러짐)**: 로봇이므로 사망 아님. 행동 불능, 자력 회복 불가.
  - ⚠ enum 정리 필요: Player 상태의 `Die`를 '다운'으로 쓸지, 별도 `Down` 상태를 추가할지 결정 (10-2).
- **구조(리바이브)**: 동료가 다가가 채널링 T초로 부활 → 협동 핵심 장치.
- **방치 시**: 계속 다운. 개인 방치 자체는 게임오버가 아니라 인원 손실→할당량 압박의 자연 페널티로 작동. **단, 플레이어 전원 다운 시 즉시 게임오버**(9-3).
- **본부 연동**: 본부가 미니맵·CCTV로 다운 감지 → 무전 알림(4-4) → 현장 동료가 구조 이동. 본부·통신 가치 강화.
- ⏸ 보류: HP 최대치, 데미지 수치, 구조 채널링 시간, HP 회복 수단(본부 복귀 회복 / 회복 아이템 등).

> **아군 오사 — 테이저로 동료를 맞추면 기절한다 (2026-07-28 확정, #252, 구현됨).** 아군 오사 규칙이 GDD에 없어 이번에 신설한다. 테이저는 조준 사격(hitscan)이라 사선에 있는 동료를 실제로 맞추는데, 그동안 아무 일도 일어나지 않아 "맞췄는데 왜 멀쩡한가"가 됐다.
> - **허용한다. 페널티는 붙이지 않는다** — 사고가 웃음이 되는 쪽이 이 게임 톤에 맞고, 쏜 사람에게는 이미 쿨다운(5초)이라는 대가가 있다.
> - **5초 쓰러져 있다가 스스로 일어난다** — 구조가 필요 없고, 구조 대상 히트박스도 켜지지 않는다.
> - **전멸(게임오버) 판정에 포함되지 않는다** — 곧 일어날 사람을 세면 아무도 잃지 않았는데 게임오버가 뜬다. 같은 이유로 오검거 매달기(#101)도 이번에 판정에서 빠졌다.
> - **이미 무력화된 동료에게는 걸리지 않는다** — 다운을 기절로 덮어써 구조 대상에서 빼버리는 사고를 막는다.
> - **쓰러진 동안 시야는 돌릴 수 있다** — 몸은 누운 채로 두고 카메라만 좌우 ±100°와 제한된 상하 범위로 움직인다. 몸까지 돌리면 누운 캐릭터가 바닥에서 제자리 회전한다. **다운(HP 0)도 같은 규칙을 쓴다** — 구조를 기다리며 주변을 볼 수 있어야 하고, 두 상태에서 조작이 달라야 할 이유가 없다.
> - 모션은 다운과 **같은 Knockdown 세트**(쓰러짐→바닥→기상)를 쓴다 — 맞는 즉시 쓰러진다. 처음에는 구조 대상인지 눈으로 구분되게 다른 클립(`Stun01`)으로 갈랐는데, 그건 NPC **제압 그로기**의 클립이라 선 채로 비틀거렸다. 카메라만 바닥 높이로 내려가 몸과 어긋났고, NPC 기절도 실은 `Knockdown01 - Ground`로 쓰러져 있다(7-4의 "서서 헤롱대는 그로기가 아니다"와 같은 취지) — **기절은 쓰러진 자세**로 통일한다. 구조 대상 구분은 모션이 아니라 구조 히트박스가 맡는다(기절엔 안 켜진다).
>
> **무력화 3종 비교** — 행동을 막는 것은 같고 **풀리는 방식**이 다르다 (코드상 `IncapacitationCause`):
>
> | 원인 | 해제 | 구조 대상 | 전멸 판정 | 모션 |
> |------|------|-----------|-----------|------|
> | HP 0 다운 (#105) | 동료 구조만 | O | O | Knockdown (쓰러짐→바닥→기상) |
> | 오검거 매달기 (#101) | 30초 자동 | X | X | Knockdown (다운과 동일 — 전용 연출 없음) |
> | 테이저 기절 (#252) | 5초 자동 | X | X | Knockdown (다운과 동일) |
>
> ⚠ **균형 확인 필요:** 기절 5초와 테이저 쿨다운 5초가 같아, 일어나는 순간 다시 쏘면 한 명을 계속 묶어둘 수 있다. 페널티가 없으므로 악용 여지가 있고, 기절을 4초로 줄이거나 쿨다운을 늘리는 쪽으로 조정할지 플레이테스트로 정한다.

### 7-6. 인계 방치 (초안 — 팀 검토 필요)
체포는 **완료가 아니라 시한부 상태**다. 잡아만 두고 인계하지 않으면 대상이 스스로 풀고 달아난다 — "일단 여러 명 잡아두고 나중에 한꺼번에 인계" 전략을 막고, 잡았으면 바로 데려가게 만든다. (7-2의 반대 경우)

- **방치 30초 → 밧줄 해제 후 도주형 전환.** 체포 상태로 있는 동안만 세고, 재연행하면 리셋된다.
- **마지막 5초는 소란**(6-3 패닉 전파와 같은 소란): 풀려나려는 몸부림에 주변 시민이 놀라 흩어진다 → 현장(목격)·본부(CCTV)가 눈치챌 수 있다. 예고 없이 사라지지 않는다.
- **적용 대상은 전원** — 순응형 무고 시민도 방치하면 풀고 간다. (판정 회피 목적의 고의 방치는 할당량 손해라 이득이 없다)
- **재검거 가능** — 도주 후 다시 제압하면 체포 상태로 돌아오고 타이머도 리셋된다.
- **본부 인계 판정이 끝난 대상은 제외** — 판정 후 본부에 남는 NPC의 처리는 유치장 시스템 몫이다.
- ⏸ 보류: 30초·5초 수치(플레이 테스트로 조정).

> **도주 시 수갑 회수 = 바닥 드롭으로 확정** (2026-07-22, #290/PR #297). 방치 타이머로 풀려 달아나는 대상은 그 자리 바닥에 수갑을 떨어뜨린다(`NpcCapturedState.Escape` → `DropHandcuffs()`) — 8-2 판정 후 반환과 동일 패턴이고, 수갑이 "소실되지 않는다"(8-2)는 원칙과 정합한다.

> **밧줄 이관으로 무효 (2026-07-27, #369).** 검거 수단이 밧줄로 바뀌며 밧줄은 소모형이 아니게 됐다 — 방치 탈주 시 떨어뜨릴 수갑 자체가 없다. `NpcCapturedState.Escape`의 `DropHandcuffs()` 호출은 제거됐고, 이제 상태 전이(도주/배회)만 일어난다.

## 8. 아이템 시스템

### 8-1. 인벤토리
- 용량 **3칸** (초기 기준).
- 기본 구성: 무전기(내장) / 스캐너 / 밧줄. (2026-07-27, #369 — 이전 '수갑'을 밧줄로 대체)

### 8-2. 기본 지급품
모든 인원에게 기본 지급.
| 아이템 | 용도 |
|--------|------|
| 밧줄 | 용의자 검거·연행 — 좌클릭 홀드 3초로 묶어 누운 채 끌고 이동, 기절 대상은 즉시. 좌클릭 홀드로 풀기 (#369). **1개당 1명**이라 여러 개 소지 시 동시 끌기 가능, 남이 끄는 대상에 덧걸어 줄다리기도 된다 (#390) |
| 스캐너 | 시민의 세부 정보 확인 (배터리 소모) |
| 무전기 | 기본 통신 수단 (내장) |

> **기본 검거 수단 수갑 → 밧줄 (2026-07-27, #369, 구현됨).** 좌클릭 수갑 체포가 밧줄 묶기로 대체됐다. 밧줄은 **소모형이 아니다** — NPC에 채워두는 자원이 없어 아래 "수갑 소모·반환 라이프사이클"은 **전부 제거**됐다(소모·반환·자원 게이트 모두). 검거 흐름: 밧줄 좌클릭 홀드 3초로 묶어 끌기(**반응 판정 없음** — #400에서 스캔·피격으로 옮겨졌다, 6-1), 기절(Stunned) 대상은 채널 없이 즉시(테이저 콤보), 놓기(E)는 그 자리에 세우되 줄은 유지, 좌클릭 홀드로 풀기. 무한 검거 방지 균형추는 수갑 소모가 아니라 아이템 패널티(#367)가 맡는다. 수갑 아이템은 폐기됐다(코드상 빈 스텁만 잔존). 아래 라이프사이클 서술은 **이력 보존용**이다.

**수갑 소모·반환 라이프사이클 (#229 — #369로 폐기, 이력 보존).** 수갑은 라운드 내에서 회수되는 **일시 소모품**이다 — 소실되지 않는다.

1. **체포 성공 시 소모** — 채널링 성공으로 대상을 처음 연행하는 순간, 잡은 플레이어의 인벤토리(3칸)에서 수갑이 빠져 대상 NPC에게 옮겨간다(전 피어 동기화). 채널링이 도주·저항·취소로 실패하면 소모되지 않는다.
2. **커스터디 동안 대상이 소지** — 대상은 수갑을 찬 채 연행·체포(놓기)·재연행·유치장 이송을 거친다. 놓았다 다시 잡는 재연행은 수갑을 **추가로 소모하지 않는다**(이미 대상이 차고 있음).
3. **인계존 판정 후 반환** — 판정이 끝나면(현상수배범·경범죄 수감이든, 오검거 석방이든) 수갑이 **연행했던 플레이어의 인벤토리로 회수된다**. 인벤토리(3칸)가 꽉 차 있으면 기존처럼 **판정 위치 바닥에 떨어진다**(아무나 다시 주워 재사용). (2026-07-23 확정, #307 — 이전의 '항상 바닥 드롭'을 대체. 단, 아래 방치 탈주는 예외로 바닥 드롭 유지)
4. **수갑이 없으면 체포 시도 불가** — 수갑을 소모해 든 게 없는 동안에는 새 체포(수갑 채널링·도주 제압)를 시작할 수 없다. 재연행(E)은 이미 대상이 수갑을 차고 있으므로 예외. 결과적으로 **수갑 1벌 = 동시 진행 체포 1건**(7-2 동시 1명 연행 제약과 정합).

> 인계 **방치** 시 대상이 수갑을 풀고 달아나는 경우(7-6)도 **판정 후 반환과 동일하게 바닥 드롭**으로 확정됐다 (2026-07-22, #290/PR #297) — 풀려나는 위치 바닥에 수갑을 떨어뜨린다.

### 8-3. 추가 아이템
검거 수익으로 구매 가능 (예시).
| 아이템 | 효과 |
|--------|------|
| 신호 해석기 | 본부에서 모든 인원에게 짧은 메시지 전송 |
| 테이저 건 | 어떤 상태의 NPC든 3초 무력화 (#292) — 도주·저항 대응이 주 용도. **동료를 맞추면 5초 기절**(아군 오사 — 7-5, #252) |
| 호루라기 | 오검거 페널티 감소 (일회성 — 한 라운드 사용 후 소멸 예정) |

> **밧줄은 기본 지급품으로 승격 (2026-07-27, #369).** 아래 #269 노트의 "기절 대상만"은 폐기됐다 — 밧줄은 이제 기본 검거 수단(8-2)이라 배회·도주·저항 대상까지 좌클릭 홀드 3초로 묶어 끈다(제압 타격으로 기절한 저항형 #366 포함). 8-3(구매) 목록에서 8-2(기본)로 이동했다.

> **밧줄(#269, 구현됨 — #369·#390으로 규칙 갱신):** 좌클릭으로 묶어 누운 채 질질 끌고 이동한다(`Rope`→`PlayerEscorter`가 진입 판정, 장력은 끌리는 `NpcController`가 계산). 테이저(기절)→밧줄(즉시 묶기)로 이어지는 도주형 대응 콤보가 핵심 용법이다. (대상 제한은 #369에서 전 상태로 확대 — 위 노트 참조)
>
> **"한 번에 1명"·"손이 묶인다"는 폐기됐다 (2026-07-29, #390).** 밧줄 **1개당 NPC 1명**을 묶어 동시에 끌 수 있고, 상한은 별도 수치가 아니라 **소지한 밧줄 개수**(인벤 3칸)다. 끌면서 다른 아이템도 쓸 수 있다 — 그 예외를 밧줄에만 두면 규칙이 반쪽이 되어 통째로 걷었다. 다중 끌기의 대가는 슬롯 경쟁(밧줄로 3칸을 채우면 들 것이 없다)과 무게 페널티(#398)가 진다. 여러 명을 끌면 밧줄 방향에 수직으로 부채꼴 배치되어 몸이 겹치지 않는다.
>
> **줄다리기 — 같은 대상에 여러 명이 덧걸 수 있다 (#390).** 남이 끌고 가는 중(`Escorted`)인 대상에 밧줄 좌클릭 3초로 **합류**한다. 기존 끌기는 끊기지 않는다 — **합류는 허용, 탈취는 차단**이 팀 결정이다(놓아둔 체포 대상을 남이 가져가는 것도 막는다). 참가자들의 장력은 합력으로 합성되어, 반대 방향으로 당기면 대상이 가운데서 멈춘다. 손을 떼는 수단은 둘: E로 놓고 걸어가 거리 초과로 자기 줄 끊기, 또는 좌클릭 3초로 **자기 줄만** 풀기. 밧줄이 걸린 채 인계존까지 들어갔으면 오검거 카운트·추격대 대상은 **관여자 전원**이다(7-3).
>
> *(줄다리기의 힘겨루기는 #398 이동속도 페널티가 들어와야 완성된다 — 지금은 끄는 사람을 붙잡는 힘이 없어 양쪽이 자유롭게 걸어가고 줄만 늘어난다.)*

### 8-4. 아이템 분류 축
- 소지형 vs 설치형(예: 신호 해석기)
- 소모형(예: 호루라기 — 영구 소실) vs 영구형
  - **일시 소모(라운드 내 회수)** — 수갑은 체포~판정 동안만 인벤에서 빠졌다가 판정 후 반환됐다(8-2). 현 검거 수단 밧줄은 소모형이 아니라 이 축에 해당하는 아이템이 지금은 없다 (#369). 호루라기처럼 영구 소멸하지 않는 별개의 하위 축이다.

## 9. 경제 & 게임오버

### 9-1. 보상
| 검거 대상 | 보상 | 상태 |
|-----------|------|------|
| 현상수배범 | 10,000원 | 구현됨 |
| 난동꾼 (거리 난동자·나체 난동꾼) — 돌발 이벤트 | 이벤트별 설정값 (`SpawnedNpcEvent`, 기본 50원) | 구현됨 (#106) |
| 경범죄자 (위조 정보 소지) | 1,000원 | *다음 빌드* |
| 그 외 전부 (오검거) | 0원 + 페널티 | 구현됨 |

> **수사 대상 수입원은 현상수배범 검거(10,000)뿐이다.** 진범이 아닌 대상을 잡으면 도주·저항 여부와 무관하게 전부 오검거(0, 페널티)다 — 6-2 미끼 행동 모델 참조.
>
> **경범죄는 두 갈래이며 서로 다른 축이다. 혼동하지 말 것:**
> - **난동꾼 경범죄 (구현됨)** — 돌발 이벤트로 스폰된 거리 난동자·나체 난동꾼을 제압·인계하면 즉결 처리되는 현장 수익 (6-4, 7-4). 수사(진범 대조) 대상이 아니라 라운드 할당량에도 포함되지 않는다. 2026-07-15 팀 확정으로 추가 (#106). **같은 개체의 수익은 첫 인계에만 지급된다** — 탈옥으로 방출된 경범죄자를 재검거해도 판정은 경범죄(오검거 아님)지만 수익은 0 (2026-07-23, #310).
> - **위조 정보 경범죄 (다음 빌드)** — 스캔으로 위조 정보를 발견해 검거하는 **데이터 기반** 수입원(1,000). 위조 정보 시스템과 함께 다음 빌드로 미룬다 (6-2).
>
> 즉 "경범죄자(1,000)를 미룬다"는 것은 **위조 정보 축에만** 해당한다. 난동꾼 수익은 이미 유효하다.

### 9-2. 자금
- 검거 수익은 **팀 공용 자금**으로 합산되어 아이템 구매에 사용.
- 팀 자산은 **0 밑으로 내려가지 않는다** (마이너스 방지).
- 오검거는 자금에 영향 없음 (보상 없는 대상이므로 자연스럽게 수익 0).
- **정산은 라운드 종료 시점 1회, 유치장 점유 기반** (2026-07-23 팀 확정, #340). 판정 즉시 지급이 아니라, **라운드가 끝날 때 유치장에 실제 수감돼 있는 대상(현상수배범 + 경범죄자)의 보상 합**을 자금에 더한다.
  - 이전의 "탈옥해도 이미 지급된 자금은 되돌리지 않는다"(#231 당시 스펙)를 대체한다. 이제 **탈옥해 유치장에 없는 대상은 정산에서 빠지고**(못 받음), 탈옥→재검거해 종료 시 다시 수감돼 있으면 1회만 계상된다 → 재검거 중복 지급이 구조적으로 없다(현상수배범·난동꾼·위조범 공통).
  - **이송 중(판정 완료·유치장 도착 전) 라운드 종료 시 해당 대상은 보상 없음** — 물리 점유(수감 완료)만 인정한다.
  - **할당량(목표 금액) 진행도도 같은 유치장 점유에서 나온다** (2026-07-28, #395). 즉 라운드 중에 보이는 진행 금액과 종료 시 정산액이 같은 근거를 본다 — 탈옥해 유치장에서 빠지면 진행도도 즉시 줄어든다("끝까지 데리고 있어야 인정").
  - 진행도는 **팀 자금(TeamFund) 잔액이 아니다.** 팀 자금은 세션 이월분이라 이전 라운드 몫이 섞여 있고 상점 구매로 줄어든다 — 이번 라운드 성과가 아니다.

### 9-3. 게임오버
다음 중 하나라도 충족 시 게임오버:
- **라운드 목표(할당량) 미달성** — 제한시간 초과 시점에 **목표 금액 미달** (#395). 목표를 넘겨 있으면 종료 버튼을 누르지 않았어도 성공으로 끝난다 — 버튼은 *일찍 끊는* 수단이지 누르는 걸 잊으면 지는 함정이 아니다.
- **플레이어 전원 다운** — 전멸. (개인 다운 방치는 게임오버 아님, 7-5)

## 10. 기술 사양 & 구현 규약

### 10-1. 플레이어 스탯
- **HP (내구도)** — 작동 규칙(데미지·다운·구조)은 7-5 참고
- 인벤토리 용량: 3칸

### 10-2. 상태 enum
**Player:** `Idle` / `Walk` / `Run` / `Attack` / `Die` / `Dance`
**NPC (용의자 포함):** `Idle` / `Walk` / `Run` / `Attack` / `Captured` / `Stunned` / `Panic` / `Escorted` / `Jailed` / `Intruding`
- `Escorted` — 연행/끌기 중(밧줄로 묶여 누운 채 끌려 이동, #369). 수갑 연행 시절의 표시 상태를 밧줄이 그대로 재사용한다 — 인계존·이벤트 수명·가로채기 방지가 모두 이 상태를 기준으로 판정하기 때문
- `Jailed` — 인계 판정 후 유치장으로 이송·수용. 대응 Animator 상태가 없어 이송 중 Escorted, 수용 후 Captured 모션을 대신 쓴다
- `Intruding` — 돌발 이벤트(범인 탈출)의 침입자가 자물쇠까지 이동 후 해제를 진행하는 상태. Jailed와 같은 예외로 Walk 모션을 대신 쓴다

### 10-3. 몽타주(외형) 표현 방식
- 몽타주 축: **머리스타일 / 머리색 / 피부색 / 수염 / 모자 / 안경** (6축). 몽타주가 서술하는 축은 화면 외형과 100% 일치하며, 전체가 아닌 **부분집합**을 서술할 수 있다. 상세 설계는 [appearance-montage.md](appearance-montage.md).
- **표현 방식(구현): 글 방식** — 공개 축을 텍스트로 나열("머리색: 빨강 / 수염: 콧수염"). 무전 구두 전달이 핵심 재미. `AppearanceDatabase.BuildMontageText`가 자동 생성하고 수배 UI(#58)가 표시한다.
- **표현 방식(예정, 실험): 픽셀(모자이크) / 실루엣** — NPC 렌더에서 자동 파생. 플레이 테스트로 병행 비교 후 확정 (appearance-montage §7).
- **외형 생산 2경로**: Generic 프롭 조합(조합형 난이도) + SciFiCity 모델 카탈로그(개성). 색 팔레트 노이즈는 비몽타주 난이도 레버.
- 외형은 종족(인간/안드로이드)을 드러내지 않는다 — 종족은 스캔 전용.

### 10-4. 예상 기술 스택
- 데이터(프로필·대조·스탯): **ScriptableObject**
- NPC AI: **FSM + NavMesh**
- CCTV: **Cinemachine** (검토)
- 멀티플레이: 온라인 협동 (UGS Netcode)

### 10-5. 네이밍 컨벤션
| 접두사/규칙 | 대상 | 예시 |
|------|------|------|
| `m_` | private/protected 인스턴스 멤버 | `m_health` |
| `s_` | static 멤버 | `s_instance` |
